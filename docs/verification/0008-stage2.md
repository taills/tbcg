# 0008 第二阶段：独立单物品构建验证记录

**状态：**单物品隔离构建纵切片已于 2026-10-07 实现并验证（Go/真实 PostgreSQL/HTTPS 管理 API/React/Firefox 与真实 worker 进程）。任务 0008 仍进行中：完整 Game 快照、runtime owner 激活与确认、公开 bundle 读取和 Godot 读取尚未实现。

## 验收边界

本记录覆盖：Publisher 读取已批准构建候选、带 `Idempotency-Key` 的构建入队、durable job、独立受限 worker 进程、确定性 `single_item` manifest/public/private 包、私有产物存储，以及 `built` Release 登记与查询。

本记录**不**覆盖，也不得据此宣称：

- 完整 Game 运行快照或多物品 Release；`capabilities` 为空。
- 激活：本阶段只登记 `status = built` 且 `activated_at IS NULL` 的 Release，不修改 Realm 活动指针。
- 公开 bundle HTTP 分发、Godot 客户端读取、私有字段在客户端路径的不可达验收。
- 对抗性隔离：worker 是只运行仓库可信代码的受限进程边界，不是恶意代码沙箱；本地测试中 worker 与测试同 OS 用户运行，不证明 OS 级隔离（生产要求独立 OS 身份）。
- 远端 CI：本记录全部为本机验证。

## 已实现能力

- **契约**：`contracts/admin/openapi.yaml` 中 `listBuildCandidates`、`startBuild`、`getBuildJob` 标记为 supported。POST 绑定 exact `content_id + integer revision + body_hash`，需要 Origin、CSRF、Game 级 Publisher 角色与 16–128 字符的 `Idempotency-Key`。状态码：202（已持久化）、409（`idempotency_conflict`、`build_conflict`、`build_already_active`、`build_profile_unavailable`、`asset_unavailable`、`asset_manifest_mismatch`、`build_input_rejected`）、429 `build_queue_full`、503 `build_outcome_unknown`（用同一 key 重试）。只有 store 实现窄接口 `BuildStore` 时才注册这些路由，不存在占位成功路由。
- **冻结输入**：入队事务读取 exact 已批准 revision 并复核 canonical body hash；对逐 Game 受控 profile 行加 `FOR SHARE`，与 provisioning 更新线性化；冻结 canonical Definition、profile（含 `profile_version` 与原始资产 manifest SHA-256）、Schema fingerprint、代码固定 builder 版本，以及从受信 `games/<gameId>/assets` 读取并校验过的原创资产字节和原始 manifest 字节。SQL 再次校验冻结 manifest 字节的 SHA-256 等于 profile。profile 只能由部署主体维护，浏览器与 Publisher 无法提交。
- **幂等与配额**：幂等作用域为 Game/actor/key，请求 fingerprint 覆盖 Game 与 exact 身份。Game 计数器行锁内先重查 key，再对同一 revision 已有排队/运行/待重试作业返回 409，每 Game 活动作业上限 20（429，不建行、不消耗版本）。Release 版本在锁内分配，允许空洞，重试不重编号。
- **角色与权限**：迁移要求外部预置 `tbcg_content_build_owner` / `tbcg_content_build_worker`（NOLOGIN），owner 除迁移执行者外不得有成员，worker 成员不得同时属于 admin/owner。admin 角色只获 5 个、worker 角色只获 4 个 SECURITY DEFINER 函数的 EXECUTE；两者都没有 build、Release 或 runtime 表的直接权限。函数 `search_path = pg_catalog, pg_temp`。admin 与 worker 的连接启动守卫拒绝 DDL、对象所有权、直接/继承表权限与跨角色成员资格；worker 进程强制 verify-full TLS。
- **Worker**：`server/cmd/content-build-worker` 单执行槽。认领使用 `FOR UPDATE SKIP LOCKED`、随机 claim token、有界租约和 attempt；同一 worker ID 重启时取回自己未过期的作业并续租。过期租约转为 `retry_wait`/`failed`。完成函数校验 token 与租约，并要求 manifest 键集合精确、数值 jsonb 相等、资产条目与冻结清单行完全一致，然后在同一事务中登记 `built` Release、唯一一条 entry、job 完成与审计。数据库明确拒绝的完成报告记为不可重试的 `completion_rejected`；提交结果未知时由同一 worker 确定性重放。
- **产物**：纯 builder 生成确定性包，不含 job/时间/attempt/路径。私有存储要求非符号链接的 0700 根目录，按 Game 建 0700 子目录，按 public → private → manifest 顺序原子 no-replace 安装 0600 文件（复用 0007 的 `InstallImmutable` 语义）。相同字节可重放，不同字节冲突，不覆盖。
- **不可变性**：job 冻结输入与终态不可改；版本计数器单调；build owner 只能插入未激活的 `built` Release；`release_entries` 只能加到未激活的 built Release，非 owner 插入对父 Release 加 `FOR SHARE` 与激活串行化，已有 entry 不可更新/删除/截断。
- **Publisher UI**：`admin/src/features/build/` 仅对 Publisher 渲染。结果未知（503、网络、5xx、408、429）时保留原 key 与请求体，只提供“用同一请求重试”；只有明确的 4xx 拒绝才允许新 key。轮询按 job 独立计数、同一时刻只有一轮在飞、核对全部身份字段、不回退终态，达上限后提供“检查状态”。`built` 显示“已构建，尚未激活”，只展示公开包 hash。

## 复审

- 首轮四份独立复审（Go、数据库、安全、TypeScript）均无 CRITICAL；TypeScript 2 个 HIGH，各复审合计若干 MEDIUM：未知结果与 5xx 的 key 处理、轮询身份绑定与竞态、入队配额、续租累加、finish manifest 校验不足、非 superuser 迁移执行、确定性 finish 拒绝导致反复重启、资产 I/O 错误映射等。全部已修复并补测试。
- 修复后的定点复核确认 11 项修复正确，另发现 1 个 MEDIUM：较短的续租请求会与“租约只能延长”的触发器冲突并抛错。已改为仅在能延长时更新、否则如实返回是否仍持有，并补充回归用例；同时为 manifest 键排序固定 `COLLATE "C"`。最终无未处理的 CRITICAL/HIGH/MEDIUM。

## 已知限制与后续

- worker 调度为全局 FIFO；跨 Game 的影响受每 Game 20 个活动作业上限约束（单物品构建为毫秒级），公平调度留待多 worker 阶段。
- job、私有产物与 built Release 没有保留/清理策略。
- 0007 `release.Publisher` 仍可用外部给定的版本号直接写 Release，不经过计数器；冲突时由唯一约束 fail-closed，统一分配器不在本阶段范围。
- 同一 worker 角色内的 instance ID 由调用方自报，只用于恢复与单 running 约束，不是跨 worker 的安全边界。
