# 0008 控制面第一纵切片验证记录

**状态：**控制面第一纵切片于 2026-10-04 初验，并于 2026-10-05 完成最后 ACL、响应身份校验及测试 fixture 补强后的复验；任务 0008 仍进行中，隔离构建、真实 runtime owner 激活、Godot 公开包读取与完整发布链路尚未完成。

## 验收边界

本记录只覆盖管理控制面：管理员登录/session、CSRF、Game 绑定 RBAC、Author 草稿编辑与 CAS、Schema/许可 manifest 校验、不可变 revision 提交、Reviewer 对 exact `content_id + revision + body_hash` 审批、审计事务、受控本地 bootstrap、可信 TLS 管理 API 与 React/Firefox 浏览器业务路径。

本记录不覆盖以下内容，且不得据此宣称任务 0008 完成：

- Publisher 隔离构建作业、Release manifest/package 与 hash 可重现产物。
- 真实游戏 runtime owner 对激活请求的加载、校验和确认。
- Godot 客户端读取公开白名单 bundle，或静态路径验证私有字段不可达。
- 完整“内容发布 → 运行时激活 → 游戏内获得物品”的端到端链路。

## 已验证能力

- 管理 API 使用冻结的 `contracts/admin/openapi.yaml` 轮廓：session/login/logout、`POST /games/{gameId}/item-drafts`、opaque `draftId` 读写/validate/submit、review queue 和 exact revision 审批；`content_id` 仅在请求体或查询参数中出现，不作为资源路径段。
- 只有 CAS `draft_version` 使用十进制字符串；Definition/public projection/Revision/Approval revision 均为 1..2147483647 的整数。
- Author、Reader、Reviewer、Publisher 按 Game 绑定；Reviewer 才能审批，Publisher 不隐式继承 Reviewer 权限。Publisher 构建/激活和 runtime owner 确认仍是后续阶段。
- 真实 PostgreSQL 迁移要求预置受限 `NOLOGIN tbcg_admin_control_plane`，应用登录成员连接后 `SET ROLE`。列级 ACL 只开放控制面需要的字段，拒绝写 `games`、`realms.active_release_id`、`owner_guards`、`characters` 等运行面/玩家数据。
- 003 migration 不删除集群级角色或其他数据库 ACL；测试覆盖 down 后角色/membership 保护、role replication、六类重叠权限拒绝、owner guard 与 content revision 的不可变/身份保护。
- 受控 `admin-bootstrap` 只通过确认标记和 env 输入创建/绑定账号与审计；账号 CRUD/HTTP route 不存在，密码不打印。本地验证曾复现 actor_id/resource_id 参数冲突 RED，修正为生产 cast 与 CLI race 后 GREEN。最后追加多主机配置反例，主机及全部 pgx fallback 均须为 loopback；非本地 fallback 在连接前拒绝，无远程测试访问。
- 控制面数据库启动守卫同时检查 `current_user` 和 `session_user` 的直接/继承列级与表级权限；除运行面数据外，也拒绝 `admin_users`、`admin_role_bindings` 的 INSERT/UPDATE/DELETE/TRUNCATE 额外权限，以及 `content_revisions`、`audit_logs`、`revision_approvals` 的 UPDATE/DELETE/TRUNCATE。账号口令及角色分配仍由受控 bootstrap/部署主体负责。账号/RBAC 列级与审计/审批篡改反例均有真实 PG RED→GREEN 记录；最终拒绝断言要求错误来自权限守卫，并验证撤销额外权限后最小角色恢复可启动。
- 登录/session 使用服务端随机 token hash、CSRF hash、absolute/idle expiry；匿名角色从 `nil` 规范化为 `[]`，避免 JSON/HTTP 形态不一致。bcrypt known-wrong 多次失败测试期望修正为 1 次错误记录。
- 浏览器管理面走 HTTPS-only；cookie 为 Secure、HttpOnly、SameSite 且无 Domain。旧的 HTTP loopback 浏览器例外不再作为文档承诺。DB-owned 隔离测试可使用 NoTLS 本地专属集群；生产和业务 E2E 使用 PostgreSQL `verify-full` 与受控 CA。
- React 管理端覆盖受控登录、字段式 item 编辑/公开预览、Schema Unicode/code point 边界、AJV 8.20 standalone ESM 校验器、CAS 冲突保留本地输入与显式 reapply、Reviewer 队列、权限恢复。API 边界拒绝 revision 与嵌套 Definition 身份不一致、审核队列/提交响应跨 Game、审批响应与请求的 Game/content/revision/hash/decision 不一致。该校验防止客户端作用域混淆，不代替服务端鉴权；提交响应不含 draft_id，不能宣称客户端在这一层验证了未知的草稿/内容对应关系。生产 bundle 检查无 `Function`/`eval`/`require`，不需要 `unsafe-eval`。AJV standalone helper 保留上游 MIT 来源说明，不把该 helper 重新许可为项目自有实现。
- Firefox 真实浏览器 E2E 使用真实 admin server、生产构建 React、PostgreSQL 管理 API、每轮随机 appDB/login/role/profile/server 与私有 CA/NSS profile；不 mock API/DB，不关闭 TLS 验证，不修改系统 Keychain 或用户 Firefox profile。未信任 CA profile 必须得到 `SEC_ERROR_UNKNOWN_ISSUER`。

## 浏览器业务路径

真实 Firefox E2E 覆盖：

1. Author 两个隔离 context 触发 CAS 冲突，本地 dirty 输入保留。
2. 用户显式 reapply 后提交不可变 revision。
3. Reviewer 只对 exact hash/revision 审批。
4. Reader/Publisher 的 UI 与 API 写操作被拒绝。
5. Origin/CSRF 负向请求被拒绝。
6. Secure/HttpOnly/SameSite cookie 属性验证。
7. 双 Game scope 切换先 cancel 保留当前输入，再 accept 清理新 scope 输入；回访 demo 时已持久化草稿可恢复。
8. 第三方未信任 CA Firefox profile 返回 `SEC_ERROR_UNKNOWN_ISSUER`。

安全截图只保留首次登录页且尚未输入账号密码的画面；未启用持久化 trace/video/自动失败截图。E2E 断言范围不包含“console errors = 0”的汇总声明；未信任 CA 用例触发的 TLS handshake 日志是预期负向路径，不按失败记录。

## 已知未决与限制

- 隔离 build、Release hash 可重现、runtime owner activation receipt、公开 bundle/Godot adapter 尚未实现或验收。
- 浏览器 E2E 只证明控制面第一纵切片，不代表完整发布链路、运行时激活或 Godot 游戏读取通过。
- session cleanup 为有界批处理（每轮最多 10×100，约 5s），expired session 超过 1000/min 时可能积压；这是有上界的清理策略，不承诺无限安全吞吐。
- 新 source/key 满容量扫描最多 10k，在锁内存在有界高负载热点；容量满时新来源 fail-closed 返回 429，可能影响合法新客户端，不把该 LOW 风险写成已消除。
- 登录额度按 IP 及 IP+账号组合计数，避免攻击者占满全局用户名短窗口持续锁定其他来源的合法登录。此策略不是全局账号预算，分布式猜测仍可能发生；没有宣称已实现全局渐进风控或 MFA。该取舍经本轮审查明确，不将组合额度误称为全局 per-account 防护。
- OpenAPI Redocly 结构验证通过，但仍有 1 条 `info-license` 建议信息；项目法律 LICENSE 未在本阶段决定。
- GitHub Actions 远端 workflow 未由本记录触发；本地验证不等同于远端 CI 已通过。本轮没有修改 Python/Godot 源码，也未重跑这些未受影响的验证，不将历史前置任务结果冒充本轮新执行。
- 记录时 main-owned PostgreSQL 测试集群仍由主流程持有并接受连接；本记录不声称已停止或清理该集群。
