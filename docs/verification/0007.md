**状态：**已验收（2026-10-04；最终质量门禁及定点复核通过，本地 Git 检查点由主代理创建）

## 实现边界

- `internal/economy` 提供 PostgreSQL 单事务奖励结算、game/realm/actor/operation 作用域幂等键、规范业务载荷 SHA-256、`owner_epoch`/角色归属锁定、结果恢复，以及唯一租约 token 的 outbox 领取和事务型消费者处理。事件类型经过白名单校验且参与载荷哈希。
- 钱包余额、账本、`operation_results` 和 outbox 在同一事务内提交。只有收到提交确认才返回成功；确认丢失返回 pending。恢复查询缺少记录不代表已回滚；同键再次领取通过唯一约束与旧事务串行化，不生成新奖励键。
- `Settle` 包括重放在内始终要求当前 owner epoch 和角色授权。接管后的旧命令使用只读 `Recover` 核验已提交结果；接管进程保留原作用域键和载荷，以当前 epoch 重放。epoch 不参与业务载荷 hash。`Recover` 不代替入口身份授权，也不执行发奖。
- `internal/persistence/commit.go` 统一经济、UnitOfWork 与 Release 的提交错误分类。仅 PostgreSQL 未本地化严重度 `SeverityUnlocalized == "ERROR"` 或 pgx 确认的提交回滚表示确定失败；`FATAL`、传输错误、取消、超时及缺少严重度信息保持未知，不依赖服务器语言。
- Release 激活事务按 owner guard → realm → Release 的顺序操作。先对 guard `FOR SHARE` 并校验显式 `OwnerEpoch`，持锁直到事务结束，再比较活动指针并验证全部版本、manifest 和产物哈希。旧 owner 不得越过接管 epoch；构建、校验、存储或提交拒绝不切换活动指针。
- Release 定义和不可变产物以 game 为作用域，realm 维护各自活动指针。完全一致的 `built`/`activated` Release 可重试或被其他 realm 复用，不降级状态、不重置首次激活时间；相同 ID 的内容、manifest 或版本差异明确冲突。
- 产物路径按校验后的 GameID 隔离。新文件在可信私有目录内完整写入、Sync/Close，再通过 `os.Root.Link` 原子 no-replace 安装并同步目录。重试只复用字节一致、权限不公开的普通文件；不同或不完整的既有目标、符号链接不覆盖、不自动删除。
- artifact root 是运维配置的可信私有目录，不是客户端指定的任意路径。本切片没有 HTTP 公共文件路由；文件权限检查不是完整公共资源隔离的替代品。
- 本切片不是完整游戏运行服务或发布平台；没有添加账号会话、审核 UI、HTTP 资源分发或 Godot 管理界面。正式 owner 进程的连接生命周期和运行时激活确认继续由后续纵切片承接。

## TDD 与故障注入

首次实现的 RED 记录：非法事件类型、事件类型未参与 hash、角色归属、outbox 消费事务、Release 定义/路径隔离等测试先失败，再完成实现。真实 PG 延迟约束与提交锁等待测试还复现了断连误判和事务回滚路径。

本次恢复后的 RED 证据：

1. 本地化 `Severity="错误"`、`SeverityUnlocalized="ERROR"` 被错误归为 unknown，分类回归测试失败；新增共享分类器测试也先因 API 不存在而编译失败。
2. 添加 `Definition.OwnerEpoch` 和错误类型后，真实 PG 行为测试确认旧 owner 仍成功激活，接管没有等待激活事务，测试失败。
3. 同一 Release 同内容重试因既有产物 `EEXIST` 被拒绝，测试失败。
4. 完成分类器、guard 锁和不可变重试后，上述回归及原有故障测试通过；既有状态竞争测试继续要求原子回滚活动指针。

真实 PG 测试覆盖奖励/账本写入失败、提交前约束拒绝、提交期间断连、并发同键结算、owner 接管等待、outbox 过期租约及回调失败、Release 构建/激活/CAS/提交拒绝、游戏隔离和跨 realm 复用。补充 `TestReleaseCommitAcknowledgmentLossIsUnknownAndSameContentRetryRecovers` 使用同一真实 COMMIT 丢确认 driver，确认数据库已切换时返回 unknown，重试恢复；并发同内容发布和 builder/validator 失败后的重试通过。产物单测确认半写目标、符号链接不被修改，正常安装/复用不残留暂存文件。

`TestEconomyCommitAcknowledgmentLossRecoversCommittedReward` 对真实 PG 执行并确认 COMMIT 成功，再通过测试 driver 丢弃确认响应。它证明调用方收到 pending 后可以恢复唯一持久结果，不将提交前中止冒充提交后确认丢失。`TestEconomyCommittedResultCanBeRecoveredAfterLostResponse` 使用新的测试进程恢复数据库结果。
