## 复审（2026-10-07，两份代理复审）

- **数据库复审**（005 与运行面 SQL）：2 HIGH、9 MEDIUM。已修复：快照 finish/fail 的 NULL 三值绕过（显式判空、`IS DISTINCT FROM`、built CHECK 显式 `IS NOT NULL`）；激活确认与拒绝都在 owner 守卫事务内、先 `FOR UPDATE` 锁请求并校验影响行数，暂态错误不再永久拒绝，realms 改用 `FOR NO KEY UPDATE`；激活请求以 advisory xact lock 串行化；新表对 admin/worker 显式 REVOKE 并断言；追加型证据表只授 SELECT/INSERT；releases 增加只允许 status/activated_at 变化与合法流转的触发器；首次购买与建角上限改为先锁钱包/账号；补齐索引；claim 先回收自身过期作业；finish 校验 manifest 资产来自冻结输入；交易统一“先钱包后背包”锁序；down 只撤销 up 授予的权限、存在快照 Release 时拒绝回滚；作业/激活表禁止 TRUNCATE。
- **Go 运行面复审**：4 HIGH、8 MEDIUM。已修复：制作成功判定改用服务端随机源；战斗结算使用固定 Release、装不下的战利品舍弃并记 outbox、消耗按现有数量扣除、重试 5 次后释放参战者；断线重连/顶号经 `OnEnter` 恢复 `BattleID` 并重发战斗视图；`AddItem` 先锁行计算再写，超限返回 `inventory_full`；Realm 循环对任务/tick/激活全部 recover；幂等重放或提交未知时从数据库重载角色；交易锁定/确认必须携带 `offer_version`，提交最多重试 5 次后以 `trade_records` 为准收尾；`dungeon.leave` 非成员不写库；副本成员少于最少人数不能开始阶段；区域目标只在从区外进入时推进；断线清理保证投递；tick 使用带超时的 context；UUID 入参校验、PostgreSQL 明文回落拒绝、HTTP 限流表清理、Release 状态校验。
- **后续补充**：每连接请求已限流（100 次/秒）。**仍未处理**：`Realm.Tx`（非幂等写）提交未知时的自动重载；修复项未全部补专门的回归测试（全量回归通过）。

## 已知限制（未完成或有意简化）

- **评审**：未进行独立的 Go/数据库/安全/TypeScript/GDScript 复审；各任务需评审后才能标记“已完成”。
- **测试深度**：未逐项覆盖提交结果未知注入、进程崩溃恢复、并发竞态（如互删好友、并发踢人）、outbox 重投等故障场景；覆盖率未达 80%；Firefox 业务 E2E 未扩展到内容库/快照/激活；远端 CI 未运行。
- **进行中战斗**只存在于 Realm 内存：进程重启时未结算的战斗丢弃（不发奖励，也不会重复发放）；已提交的结算以 battle_id 幂等。
- **队伍与交易会话**是内存 owner，进程重启后解散/取消（交易在提交前不移动任何资产）。副本实例、任务、背包、经济全部持久化在 PostgreSQL。
- **runtime 数据库角色**：005 仅在部署预置了 `tbcg_game_runtime` 组时授予权限；测试使用隔离库的维护者连接。生产需为 game-server 预置专用登录并加入该组。
- **开发模式**：`TBCG_GAME_DEV_CONTENT=1` 时直接从 `games/<id>/content` 加载并标记 `dev-local`，不是已构建 Release，仅供本地联调。
- 运行面 outbox 事件与业务数据同事务写入，但尚无运行面事件的投递器/外部消费者（既有 `economy.ProcessOutbox` 只覆盖 0007 结算事件）。
- 战斗事件含 `event_seq`、`action_id`、`hit`；示例技能均为单击，多击执行器已实现但只有内核单测覆盖。
- 跨 Game 公平调度、产物保留/清理策略、0007 Publisher 自定版本号仍为既有限制。
