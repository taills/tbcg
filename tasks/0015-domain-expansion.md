## 范围

- 每次只选一个用户可见领域，并为其 Definition/Instance、权限、事务、编辑器、API、表现和回滚建立独立子任务。
- 宠物、伙伴、坐骑、制作、商店、好友、公会、跨玩家交易、活动按 PLAN 中的支持矩阵逐步推进。
- 涉及资产转移/多人并发的功能先设计数据库事务与状态 owner，再开发 UI。
- 伙伴/坐骑可复用宠物域抽出的最小 common owner seam，但不得把宠物树、伙伴和坐骑合并成一个通用 CRUD；未完成 seam 前不得并行修改同一 ownership 文件。
- 不默认实现跨服、拍卖、复杂实时活动或容量型运营系统；需要独立产品/容量设计时另开计划。

## 验收标准

- [ ] 每个领域有最低可玩故事、网页定义/发布、Go 权威事务/owner、Godot 表现、真实 PostgreSQL 与三端测试，覆盖率达到 80%+ 并通过评审。
- [ ] 资产变更同 PostgreSQL 账本/幂等结果/outbox 事务，权限与所有者约束通过测试。
- [ ] 只有实际交付、测试、评审并提交后，才更新支持矩阵为 supported；业务 Schema 存在不能视为领域完成。

## 验证

- 每个领域单独任务文件、TDD、数据库集成与必要 E2E；扩展任务不允许多个高风险经济功能打包一次提交。
- 执行性能与安全审查，并核对对既有实例和 Release 的向后兼容。
